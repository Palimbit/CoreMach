# CoreMach workspace instructions

- CoreMach owns the portable engine, components, machine systems and runtime.
  Qt6 is an optional frontend; the engine must build and test without it.
- Preserve instance-owned state, rational virtual time and platform contracts.
  Keep platform calls and file parsers outside the engine; no mutable globals.
- This repository was extracted from BluMach at the immutable commit recorded
  in doc/architecture/coremach-extraction.md. Preserve authors, SPDX notices,
  provenance origin commits and the versioned history correspondence. Do not relicense
  or present adapted code as an original implementation.
- Every component change requires meaningful tests and a provenance update.
  Run tools/provenance_audit.py before publishing.
- Firmware/BIOS, operating systems and disk images are local inputs only.
  Never commit them or modify archival originals. Use read-only inputs or
  disposable working derivatives. Never run infected or unscanned media.
- Canonical research records live outside Git in Z:/library. Before machine
  implementation/validation, read its README, manifest and latest worklog.
  Update canonical records after significant validation, preserving history.
- src/qt/catalog/source is the editable catalogue source. Runtime catalogue
  artifacts are generated by tools/catalog_builder.py; do not commit them.
  Configuration choices must come from supported documented machine data.
- Build local Windows Qt applications through MSYS2 UCRT64 with Qt6. Use
  tools/run-blumach-portable.ps1 for launch; do not execute the GUI directly.
- Keep experimental PCS286 and timing limitations visible. POST is not proof
  of full hardware fidelity. No stable ABI is promised in 0.2.0-dev.

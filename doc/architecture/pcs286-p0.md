## Decisions for the first implementation round

1. The existing address router stays architecture-neutral. CPU bus protocol,
   byte lanes, refresh/INTA, privilege and native fault signalling are not ISA
   concepts and must not become mandatory fields of all CPU accesses. Native
   protocol adapters may wrap the router when an actual consumer needs them.
   No generic pin-level API or asynchronous request API is introduced here.
2. `bm_at_bus` is a PC board interconnect, not the universal CPU bus. Guest
   register width, external data width and expansion connector width differ.
   The CPU splits its architecturally unaligned accesses; the board splits
   target-width/decode boundaries. Neither silently retries a completed write.
3. New 286 access endpoints start `wait_states` at zero and return TOTAL extra
   requester clocks. Legacy endpoint conventions remain unchanged. Inner device
   durations must be converted before addition, not added as raw clock counts.
   Sum sequential fragment durations exactly, round UP once per transfer, then
   include the result once in CPU elapsed cycles. No rounding credit crosses
   independent transfers; no float, saturation or silent overflow.
   Clock-edge alignment and overlapping transactions require a later measured
   protocol model. These rules are a modelling policy, not a measured GC102 wait
   table. Unknown hardware timings remain unknown, not implicit zero waits.
   Headland routes carry explicit wait quality (unknown/documented/provisional).
   The board-supplied AT decode callback converts its target durations and
   returns requester clocks; `at_bus` forwards those without converting twice.
   A strict adapter rejects unknown/provisional timing. A future provisional
   scheduling mode needs a named policy and must label results accordingly.
4. Lower router UNMAPPED/READ_ONLY outcomes are resolved by the board before
   reaching a CPU endpoint. Missing implementation and host failure remain
   errors, never successful open-bus responses. A future 68000 BERR, for example,
   needs native result/signalling semantics, not a cast from BM_STATUS_DEVICE_ERROR.
5. Initial AT arbitration is boundary-based: CPU owns reset state; external
   request -> HOLD outside LOCK -> CPU finishes boundary -> HLDA -> grant.
   Cancellation lowers HOLD, and CPU ownership resumes when HLDA lowers.
   Access without ownership is IDLE and has no side effects. DEBUG observes
   without arbitration or guest side effects. No synchronous mid-instruction
   retry is supported. A second simultaneous external requester is explicitly
   unsupported until a documented/tested priority policy is implemented.
6. Chip constructors do not register callbacks or execute firmware. Build all
   objects, wire contexts, then publish mappings/timed sources. Board teardown
   destroys engine callbacks before their objects. Each new constructor clears
   its output on failure and releases partial allocations. Components are
   single-threaded/non-reentrant; resets requested by I/O are latched.
7. CPU286, PIC, DMA and Headland remain separate owners. PIC chooses vectors;
   CPU accepts interrupts; AT grants access; Headland resolves memory; board
   combines A20 sources and routes NMI/reset. No PIC inside the CPU, no RAM
   allocation inside Headland, no BIOS-PC/address heuristics in generic chips.

The existing engine ABI, scheduler algorithm and PCS86/M15 implementation are
unchanged. This P0 does NOT establish electrical multi-master cycle accuracy.
The provisional `BM_GC10X_PROFILE_PCS286` is not proof of a silicon revision:
P2 must qualify its decode table against canonical evidence before implementing
or renaming it. Do not invent GC103/GC102 equivalence to close that issue.

## What the tests mean

All test sources are authored for this project. No ROM or external CPU vector
suite is bundled. Existing components retain their own provenance.

| CTest gate | Runs now? | Evidence and limitations |
|---|---|---|
| `pcs286-p0.foundation` | Yes | Real bus + real memory: big/little endian, >20-bit address, separate memory/I/O/program/data, instance isolation, explicit open bus, error propagation, DEBUG/LOCK attributes. Exact existing clock-math oracle for fractional waits and overflow. Not a Z80/6502/68000 interpreter or an AT converter. |
| `pcs286-component.cpu286` | Yes, partial lifecycle | Reset high fetch, authored NOP, instance isolation/reset, atomic state import, failure cleanup, pending-event stops and strict rejection of unknown timing. Does not certify the opcode set/protected mode/timing. |
| `pcs286-component.headland` | No implementation yet | Partial-allocation cleanup, pure repeatable route query, address bounds. Actual register/reset/mapping truth tables must be added from evidence by P2. |
| `pcs286-component.at-bus` | Yes, boundary interconnect | LOCK/HOLD/HLDA ownership, cancellation, competing-request rejection, no access on denied grant, DEBUG, wait forwarding. No physical arbitration fidelity claim. |
| `pcs286-component.at-bus-contract` | Yes | Invalid inputs, stale HLDA, idempotent pin levels, callback failure and failure cleanup. |
| `pcs286-component.cpu-at-bus` | Yes | Real partial 286 and AT components wired together: HOLD/HLDA, LOCK, DMA grant, resume/reset and requester-clock wait forwarding. Authored NOP endpoint; no firmware or real DMA controller. |
| `pcs286-component.board-memory` | Yes | Real RAM/ROM storage, interleaving, failure cleanup and isolation; actual CPU/AT wiring with an authored reset/stack/I/O program. Physical decode is a test-only linear fixture, not Headland or PCS286 POST. |
| `pcs286-component.at-pic` | No implementation yet | Programmed non-default vectors, IRQ8 cascade and independent EOIs. Full priorities/spurious/trigger modes remain required. |
| `pcs286-component.at-dma` | No implementation yet | Upper-controller address/count programming, reset masking and idle/no-grant guard. Real byte/word transfers, pages, TC, autoinit and cascade remain required. |

Acceptance sources ALWAYS compile as object files. When their implementation
target exists, the same object is linked against it and executed. There are no
replacement implementations/stubs to satisfy these tests. Until then a CTest
entry explicitly exits 77 (`Skipped`, NOT passed). CTest's overall percentage
can still say 100%: report executed passes and skipped checks separately.

`BLUMACH_REQUIRE_PCS286_COMPONENTS=ON` refuses configuration while any of these
five targets is absent. An interface-only library is rejected as implementation.
This checks availability of the initial gates, not completeness of a machine;
passing them never automatically registers PCS286 with runtime/frontends.

```sh
cmake -S . -B build/p0 -DBLUMACH_BUILD_LEGACY=OFF -DBLUMACH_BUILD_ENGINE=ON \
  -DBLUMACH_BUILD_PORTABLE_QT=OFF -DBUILD_TESTING=ON
cmake --build build/p0
ctest --test-dir build/p0 --output-on-failure
ctest --test-dir build/p0 -L pcs286-p0 --output-on-failure
```

Windows uses the UCRT64 compiler/runtime; MSVC provides a separate portability
check. Release builds retain assertions in these test targets. Test fixtures
have bounded traces; capacity exhaustion is an error, not a dropped event.

## Agent assignments after coordinator review

Every assignment must include: exact reviewed base commit; this document and
`pcs286-portable-contracts.md`; canonical `olivetti/pcs286` README/manifest/latest
worklog; read-only source commit/path references; owned files; tests and remaining
gates; and provenance classification. No agent is started by this change.

Common restrictions: preserve original notices, no proprietary assets in Git,
no mutable globals/host filesystem/Qt, no machine-ID conditionals in reusable
cores, no firmware patch/forced status/BDA writes to bypass POST. Report
implemented/partial/unsupported/timing-unknown separately. Do not weaken the
acceptance assertions merely to pass. Propose corrections with evidence.

### P1: Intel 80286

Own `components/cpu/80286/src/**` and new `tests/components/pcs286/cpu286_*.c`.
Target to supply: `blumach_cpu_80286`. Begin with an Intel documentation and
opcode/exception coverage matrix, then implement the reusable CPU, not just the
BIOS path. A passing reset test is an intermediate result only. Full acceptance:
real/protected mode, hidden caches/limits/privilege/gates/tasks, precise faults,
double fault/shutdown, interrupt shadows, absent FPU, reset and timing provenance.
Use native clocks; unknown timing must not silently become one clock.

### P2: Headland

Own `components/chipsets/headland/src/**` and new
`tests/components/pcs286/headland_*.c`. Target: `blumach_headland_gc10x`.
Sources by canonical asset ID: `headland-ht101a-ht102`, `headland-ht101a`, plus
the equivalent-platform Dario/P35 record. Inspect them locally; do not copy them
into the repository. FIRST produce register/reset/decode truth tables and flag
undocumented bits; the coordinator reviews unresolved hardware assumptions.
Then implement RAM banks, ROM/reset decode, switchable mappings, A20/requester
rules and register tests. No always-enabled diagnostic alias. P0's lifecycle
gate alone cannot approve this chip.

### P3: AT fabric

Own only `components/pc/src/at_bus.c`, `at_pic.c`, `at_dma.c`, their private
`at_*_private.h` headers, and `tests/components/pcs286/at_*.c`.
Targets: `blumach_at_bus`, `blumach_at_pic`, `blumach_at_dma`.
Audit existing PIC/DMA logic before selective reuse. Retain its notices and
pin original paths/commit; do not label derived logic `new`. Complete byte/word
DMA and page/count/TC/mask/autoinit/cascade tests, PIC priority/spurious/cascade,
and exact wait conversion tests in addition to these initial gates. Simultaneous
request arbitration requires an explicit extension, not silent dropped requests.

Coordinator owns public headers, all CMake files, provenance, runtime/machine
registration and canonical record changes. Agents propose those changes rather
than independently altering them. Other timing/KBC/storage/video packets follow
after the interfaces they consume are tested. No claim of bootability until P8.

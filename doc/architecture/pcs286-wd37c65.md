# PCS286 WD37C65 functional controller

<!-- SPDX-License-Identifier: GPL-2.0-or-later -->

## Decision and provenance

The private PCS286 diagnostic composes `bm_wd37c65` at the standard AT split
ports `3F0h`-`3F5h` and `3F7h`; `3F6h` remains available to the ATA alternate
status/control register.  The implementation derives its instance-owned command,
result, drive and bounded-sector policy from BluMach's existing `bm_fdc765`
component and retains the inherited authors and GPL notice.  It does not import
another emulator implementation or create a shadow 8237.

The [Western Digital WD37C65/A/B data sheet](https://bitsavers.org/components/westernDigital/_dataSheets/WD37C65.pdf)
defines the main-status bits and command phases.  The NEC uPD765-compatible
command set remains the basis of the inherited functional core.  These sources
document the controller family; they do not prove the exact PCS286 suffix,
oscillator, drive wiring or physical timing.

## Implemented functional boundary

- DOR reset/enable, MSR, data register, DIR and data-rate register.
- Reset-sense sequence and IRQ/DREQ line ownership.
- Specify, Sense Drive Status, Recalibrate, Sense Interrupt Status, Read ID,
  Seek and Version commands.
- DMA Read Data and Write Data through byte endpoints owned and scheduled by
  `bm_at_dma_t`.  Terminal count ends a complete sector; an early count produces
  the controller's overrun result.
- Maximum sector size 4096 bytes before any media callback.
- No medium and write protection are guest-visible result bytes.  A block
  backend failure remains a host status and is never converted into a guest CPU
  exception or a successful controller result.
- DEBUG reads are observational.  DEBUG writes reject.

The component leaves non-DMA execution and physical motor, seek, rotational,
data-rate and interrupt timing unsupported.  Its `advance` method therefore has
no scheduled edge and `next_deadline` returns idle.  The functional path is
sufficient to expose a real idle MSR (`80h`) to the POST and to transfer sectors
through the tested AT DMA endpoint; it is not a claim of cycle-accurate WD
silicon.

## BIOS boundary

BIOS 1.42 routine `F000:3DAA` asserts DOR reset with `00h`, releases it with
`0Ch`, then polls MSR bit 4 at `3F4h` until controller busy clears.  The previous
unclaimed-port value `FFh` kept the bit set through all 256 iterations and was a
real guest diagnostic failure, even though the emulator itself continued with
status OK.  An idle installed controller returns `80h`; no BIOS-address or
firmware-value condition is involved.

The current diagnostic has no drive attached.  Media selection, immutable
original plus writable overlay policy, DMA bus coordination during real BIOS
transfers and the resulting INT 13h boot path must be validated separately.

## Tests

The focused component test covers reset/MSR and four reset-sense results,
command/result phases, absent media, IRQ/DREQ transitions, a complete read and
write, early terminal count, DEBUG access, backend failure propagation and an
actual 512-byte WD37C65-to-AT-DMA-to-memory transfer.  The authored CLI test
executes DOR reset/release through the real board decoder and distinguishes
`80h` from the former `FFh` hole response.  No preserved firmware or media is
compiled into either test.
